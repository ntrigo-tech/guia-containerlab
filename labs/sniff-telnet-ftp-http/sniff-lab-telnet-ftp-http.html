Lab de Sniffing: Telnet · FTP · HTTP

2 PCs Linux + 1 switch OVS. Tres servicios para capturar.

Idea del lab: pcB corre tres servicios clásicos sin cifrado (Telnet, FTP, HTTP con Basic Auth). Desde pcA, cada estudiante abre una shell vía TopoViewer y prueba el servicio que quiera, capturando con tcpdump y revisando el .pcap en Wireshark — las credenciales quedan visibles en texto plano en los tres casos.

Módulos — se trabaja en los tres

1. Telnet

PUERTO 23

Qué es / para qué sirve: protocolo de acceso remoto a terminal, de los años 70. Permite loguearse y ejecutar comandos en otra máquina como si estuvieras sentado frente a ella. Hoy prácticamente en desuso para administración real.

1

En pcB o pcA, arranca la captura:

tcpdump -i eth1 -w /capturas/sniff_capture.pcap
2

Desde pcA, conéctate:

telnet 10.0.7.2

Usuario: telnetuser — Contraseña: telnet123

tipear ls -l y luego exit

2. FTP

PUERTO 21

Qué es / para qué sirve: protocolo para transferir archivos entre cliente y servidor (subir/bajar). Muy usado históricamente para mantener sitios web o compartir archivos en red.

3

Desde pcA, lee el archivo "secreto" con curl (sin instalar nada extra):

curl ftp://ftpuser:ftp123@10.0.7.2/secreto.txt

Usuario: ftpuser — Contraseña: ftp123

3. HTTP con Basic Auth

PUERTO 80

Qué es / para qué sirve: protocolo base de la web. Con Basic Auth, el servidor pide usuario/contraseña antes de mostrar contenido — muy simple, pero las credenciales solo van codificadas en Base64, no cifradas.

4

Desde pcA:

curl -u admin:miclave123 http://10.0.7.2/

Usuario: admin — Contraseña: miclave123

5

Detén la captura (Ctrl+C), saca el archivo y ábrelo en Wireshark: filtro telnet → clic derecho → Follow → TCP Stream. Verás cada carácter tecleado, incluida la contraseña.
Para bajar el archivo .pcap, fijarse que está disponible para descargar en el menú de la izquierda en la parte media, una vez identificado, ir a los 3 puntos a la derecha del nombre y elegir la ópcion download.

6

En Wireshark, filtro ftp → verás los comandos USER ftpuser y PASS ftp123 viajando en texto plano en el canal de control.

7

En Wireshark, filtro http.authorization → el header Authorization: Basic YWRtaW46bWljbGF2ZTEyMw== aparece directo. Decodifica con:

en Linux: echo "YWRtaW46bWljbGF2ZTEyMw==" | base64 -d  En WEB: https://www.base64decode.org/

¿Por qué en producción se usa SSH, SFTP y HTTPS en su lugar?

En claroReemplazo seguroQué cambia
TelnetSSHToda la sesión (login + comandos) viaja cifrada; además usa intercambio de claves para autenticar al servidor, evitando que un atacante suplante la máquina destino.
FTPSFTP (sobre SSH)Mismo cifrado de SSH aplicado a transferencia de archivos — usuario, contraseña y contenido del archivo quedan protegidos. (No confundir con FTPS, que es FTP + TLS, otra variante también válida.)
HTTP Basic AuthHTTPS (HTTP + TLS)TLS cifra toda la conexión antes de que viaje cualquier header, así que el Authorization: Basic ... nunca se ve en claro en la red, aunque la codificación Base64 sigue siendo trivial de revertir si alguien lograra romper el cifrado.
Punto clave para la clase: en los tres casos el cambio no es "una contraseña más larga" — es que el canal completo se cifra (SSH) o se envuelve en TLS (HTTPS/SFTP sobre SSH), así que capturar los paquetes con tcpdump ya no sirve de nada: lo que se ve es tráfico cifrado ilegible, no texto plano.
